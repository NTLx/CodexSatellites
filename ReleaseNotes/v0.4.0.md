# CodexSatellites v0.4.0

Adds full settings access directly inside the Small and Medium widgets.

## Highlights

- Both widget sizes now have a top-right gear that switches between the quota face and a compact settings face.
- The settings face exposes the same four controls as the notch Settings Bar: Launch at Login, quota check frequency, read-only available reset count, and Quit.
- The normal face change uses a short Y-axis flip; Reduce Motion uses a non-3D fallback.
- Macs without a usable hardware notch can now reach CodexSatellites settings through the widget. There is still no conventional Settings window or menu bar item.

## Widget interactions

- Clicking non-gear quota content keeps the v0.3.1 cache-only reload behavior. It never fetches from OpenAI, reads Codex auth, starts the app, or writes the quota snapshot.
- The gear changes only widget-local presentation state. Small and Medium face state are stored independently.
- Launch, frequency, Review Login Items, and Quit actions route to the existing main-app behavior through a shared App Intent dispatcher instead of reimplementing settings logic in the extension.
- Launch at Login continues to use `SMAppService.mainApp` as the sole source of truth.
- Frequency still cycles exactly `1m → 5m → 15m → 1m`; changing it replaces the existing refresh loop without triggering an immediate quota request solely because the interval changed.
- Reset count remains noninteractive. Fresh `0` is shown as `0`; stale or unavailable quota state shows `—`.
- Quit terminates the current app instance without unregistering Launch at Login.

## State model

- Quota data remains in the existing `WidgetQuotaSnapshot` contract.
- v0.4.0 adds a separate app-owned `WidgetSettingsSnapshot` for Launch-at-Login state, refresh frequency, and freshness-correct reset count.
- The app publishes both quota and settings snapshots through the existing `widgetContainer` transport. Developer ID signing does not implicitly switch the runtime to App Group transport.
- The widget writes only its local face selection. Multiple widgets of the same family share that family's selected face in v0.4.0.
- The widget timeline remains `.never`; no scheduled/background widget refresh, Timer, push refresh, or direct usage request was added.

## Privacy and authentication

The app remains the only component that reads the existing local Codex authentication state and calls the usage endpoint. The widget extension never reads Codex auth and never calls the usage endpoint. Settings snapshots contain only widget-safe settings state and never contain credentials.

## Requirements

- macOS 15+
- Existing local Codex CLI authentication
- A code-signed build for WidgetKit registration
- Hardware notch required only for the notch satellites; the widget works independently of notch availability

## Known limitations

- Codex usage currently depends on an undocumented ChatGPT usage endpoint.
- Full-screen Space behavior has not been explicitly validated.
- No automatic updater yet.
- Multiple Small widgets share one Small face selection, and multiple Medium widgets share one Medium face selection.
- An already-running widget extension may continue using the previous widget binary after an in-place app update until macOS recycles that extension process. No public WidgetKit API guarantees immediate recycling; Developer ID upgrade behavior remains to be verified.
